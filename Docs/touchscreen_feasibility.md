# LCD 触摸屏控制可行性说明

当前项目保留 USART1 串口作为贪吃蛇的主要控制方式。LCD 触摸屏控制作为后续扩展功能进行可行性评估，暂不替换现有串口输入。

## 参考驱动来源

野火配套例程中已经包含 XPT2046 电阻触摸屏驱动，可作为后续移植参考。

参考目录：

```text
1-书籍配套例程-F103VE指南者_20240202/29-电阻触摸屏—触摸画板/User/lcd/
```

关键参考文件：

```text
bsp_xpt2046_lcd.c
bsp_xpt2046_lcd.h
```

可参考的主要函数：

- `XPT2046_Init()`：初始化触摸屏相关 GPIO。
- `Calibrate_or_Get_TouchParaWithFlash(...)`：校准或读取触摸屏校准参数。
- `XPT2046_Get_TouchedPoint(...)`：读取触摸点坐标。
- `XPT2046_TouchEvenHandler()`：触摸事件处理函数。

## 引脚占用分析

配套例程中的 XPT2046 触摸屏使用以下引脚：

- PENIRQ：PE4
- CS：PD13
- CLK：PE0
- MOSI：PE2
- MISO：PE3

当前贪吃蛇工程已经使用的主要引脚：

- LCD FSMC 数据/控制线：PD0、PD1、PD4、PD5、PD7、PD8、PD9、PD10、PD11、PD14、PD15、PE7 到 PE15
- LCD 复位：PE1
- LCD 背光：PD12
- USART1：PA9、PA10
- LED/BEEP：PB5、PA8
- 板载按键：PA0、PC13

从目前引脚分配看，XPT2046 使用的 PE0、PE2、PE3、PE4、PD13 与当前工程主要外设没有直接冲突。PE1 已用于 LCD 复位，但触摸屏例程未占用 PE1，因此引脚方案具备可行性。

## 接入思路

建议不要直接替换串口控制，而是增加一个可选触摸输入模块。触摸输入最终也转换成现有游戏命令，复用当前移动逻辑。

建议实施顺序：

1. 先移植最小化 XPT2046 读点逻辑。
2. 通过 USART1 输出原始触摸坐标和换算后的屏幕坐标，用于验证触摸屏是否正常。
3. 完成触摸屏校准，确认坐标方向和 LCD 显示方向一致。
4. 在 LCD 上绘制虚拟方向键区域。
5. 将触摸区域转换为游戏命令：
   - 触摸上方向区域：调用 `snake_game_on_command('U')`
   - 触摸下方向区域：调用 `snake_game_on_command('D')`
   - 触摸左方向区域：调用 `snake_game_on_command('L')`
   - 触摸右方向区域：调用 `snake_game_on_command('R')`
   - 触摸开始区域：调用 `snake_game_on_command('S')`

## 推荐控制方案

优先推荐“虚拟方向键”方案，而不是滑动手势方案。

原因：

- 虚拟方向键逻辑简单，便于调试。
- 触摸区域固定，不容易误判。
- 更适合课程设计演示。
- 可以与当前串口控制并行存在，出现触摸异常时仍可使用串口继续演示。

虚拟方向键可以放在屏幕棋盘下方或开始界面中，游戏区域仍保持 20×15 网格不变。

## 风险与注意事项

- 配套例程中的 XPT2046 驱动依赖 STM32 标准外设库，而当前工程使用的是精简寄存器头文件 `stm32f103_min.h`，不能直接复制后编译，需要做寄存器级移植。
- 配套例程的触摸校准参数可能存储在外部 SPI Flash 中，而当前工程只使用内部 Flash 保存最高分。
- 触摸采样不能阻塞太久，否则会影响蛇移动刷新节奏。
- 需要确认 LCD 扫描方向和触摸坐标换算方向是否一致，否则会出现触摸位置偏移或方向颠倒。

## 当前结论

触摸屏控制从硬件引脚上看具备可行性，但建议作为后续扩展任务实施。

当前版本的可靠演示路径为：

1. USART1 串口方向控制。
2. 障碍物模式演示。
3. 上位机网页数据可视化。

触摸屏控制可在以上功能稳定后再移植和联调。
